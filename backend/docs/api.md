# X FACTOR — API Reference

Interactive documentation is generated by FastAPI:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Machine-readable schema: `http://localhost:8000/openapi.json`

All routes are prefixed with `/api` (`API_PREFIX`). In the Compose deployment the
frontend reaches them through nginx at `http://localhost:8080/api/*`.

---

## 2. Starting a workflow

Both start endpoints share one process-wide single-flight slot. While a run is
in flight, another start returns `409` with the active thread id; the dashboard
uses `GET /api/orchestration/workflows/active` to disable its Start button.

`POST /api/orchestration/workflows`

```json
{
  "thread_id": "EV-DEMO-RED-SEA",
  "request": {
    "disruption_report": {
      "event_id": "EV-DEMO-RED-SEA",
      "headline": "Militant attack closes the Bab-el-Mandeb route",
      "description": "Maersk suspended Red Sea transits ...",
      "source": "Maritime security alert feed",
      "reported_at": "2026-11-22T17:45:00Z",
      "location_hint": "Bab-el-Mandeb, Red Sea"
    },
    "scenario_request": {
      "event_id": "EV-DEMO-RED-SEA",
      "disruption_type": "Maritime Security Threat",
      "severity": "High",
      "origin": "Mumbai",
      "destination": "Rotterdam",
      "cargo_value_usd": 1250000.0,
      "container_count": 4,
      "transport_mode": "Sea",
      "current_carrier": "Maersk",
      "available_budget_usd": 500000.0,
      "risk_factors": ["..."],
      "inventory": {
        "material_id": "MAT-PHARMA-001",
        "target_plant": "Rotterdam DC",
        "demand_forecast": 20000.0,
        "committed": 2000.0,
        "average_daily_demand": 400.0,
        "lead_time_days": 7.0,
        "service_level_percent": 95.0
      }
    },
    "supplier_id": "SUP001",
    "origin_country": "India",
    "destination_country": "Netherlands",
    "transit_countries": ["Egypt", "Saudi Arabia"],
    "certifications": ["GDP", "WHO-GMP"],
    "is_high_impact_reroute": true
  }
}
```

The complete, validated payload is
[`backend/demo/mumbai_rotterdam_scenario.json`](../demo/mumbai_rotterdam_scenario.json).

Response highlights: `thread_id`, `status`, `awaiting_approval`,
`recommendation`, `decision_log`, `agent_executions`, `proposal_version`,
`approval_request` (when paused) and `errors`.

Omitted `applicable_rules` falls back to the default deterministic compliance
rules. Re-submitting the same `thread_id` continues the same checkpoint thread.

## 3. Human decision

`POST /api/approvals/{thread_id}/decision`

```json
{
  "action": "approve",
  "comment": "Validated against the deterministic audit.",
  "proposal_version": "0a2f4e993d7eb75e"
}
```

`action` is `approve`, `reject` or `request_modifications`. The approver identity
and role come from the bearer token, never from the body. The response carries
the decision record, the resulting workflow status and, after an approval, the
execution report.

### Authorisation model

`APPROVER_CREDENTIALS` is a comma-separated list of
`token:approver_id:Role` entries with Role `Manager` < `Director` < `Admin`.
Tokens are compared in constant time. Proposals have an approval level derived
deterministically from their impact; a lower role cannot approve a higher level.

| Situation | Status |
| --- | --- |
| `APPROVER_CREDENTIALS` unset | `503` (fail closed) |
| Missing/invalid bearer token | `401` |
| Role below the proposal's approval level | `403` |
| Unknown thread | `404` |
| Stale `proposal_version` or duplicate decision | `409` |
| Database unavailable | `503` |

A rejected or modification-requested proposal produces no execution report.
Execution is idempotent per `thread:proposal_version:action_type`; a repeated
approval cannot execute twice.

## 4. Dashboard reads

| Endpoint | Response shape |
| --- | --- |
| `/dashboard/overview` | `{counts, latest_runs, data_sources}` |
| `/dashboard/runs?limit=25&status=completed` | `{count, runs}` |
| `/dashboard/runs/{thread_id}` | `{run, state}` or `404` |
| `/dashboard/disruptions?limit=25` | `{count, disruptions}` |
| `/dashboard/shipments` | `{count, shipments}` |
| `/dashboard/inventory` | `{source, is_mock, materials, positions}` |

Dashboard data is a projection of real recorded runs and the seeded demo data.
Simulated SAP positions keep `is_mock=true` and the `[SIMULATED]` label.

## 5. Examples

```bash
# Health
curl http://localhost:8000/api/health

# Start the demo scenario (pauses at approval)
curl -X POST http://localhost:8000/api/orchestration/workflows \
  -H "Content-Type: application/json" \
  --data @backend/demo/mumbai_rotterdam_scenario.json

# Approve it (token from APPROVER_CREDENTIALS)
curl -X POST http://localhost:8000/api/approvals/EV-DEMO-RED-SEA/decision \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"action":"approve","comment":"demo","proposal_version":"<version>"}'

# Read the execution report
curl http://localhost:8000/api/approvals/EV-DEMO-RED-SEA/execution \
  -H "Authorization: Bearer <token>"
```

The `scripts/run_demo_scenario.py` helper performs the same flow and prints each
recorded stage.
