## 3. MANDATORY PROGRESS TRACKING

Create and continuously maintain these files in the project root:

### A. `PROJECT_PROGRESS.md`

This is the main recovery file. Update it immediately after completing each step.

It must contain:

- Project overview.
- Current development phase and step number.
- Overall completion percentage (estimate).
- Completed steps.
- Partially completed steps.
- Pending steps.
- Files created, modified, or deleted.
- Packages installed and versions where relevant.
- Environment variables configured (names only; NEVER store secret values).
- Commands required to run the project.
- Tests performed and their results.
- Known bugs and unresolved issues.
- Exact next action to perform.
- Any important architectural decisions.

### B. `DEVELOPMENT_LOG.md`

Maintain a chronological record of development.

After each step, record:
- Step number and name.
- Work completed.
- Important implementation decisions.
- Files changed.
- Tests and results.
- Problems encountered and their solutions.
- Remaining work.

Keep entries concise but useful.

### C. `TASK_CHECKLIST.md`

Create a checklist of every task from the roadmap.

Use these statuses:
- `[ ]` Not started
- `[/]` In progress
- `[x]` Completed
- `[!]` Blocked

Never mark a task completed unless its implementation has been verified.

## 4. COMPLETION AND VERIFICATION RULES

A development step is complete only when:

1. Its required functionality is implemented.
2. Relevant files are saved.
3. Required dependencies are installed or documented.
4. Relevant tests or practical verification are performed.
5. Existing functionality has not been broken.
6. Known limitations are documented.
7. All progress files are updated.

If a test fails, fix it before declaring the step complete. If it cannot be fixed, document the failure and mark the task as blocked or partially completed.

Do not claim that an integration works if it has only been mocked.
